# 如期手记 H5 单机版

## 开发与验收

沿用 uni-app / Vue 3 / TypeScript / Pinia 工程。使用项目声明的 Node 22+ 和 pnpm 10.10.0。

```sh
pnpm install
pnpm dev:h5       # 默认 http://localhost:9000
pnpm build:h5     # dist/build/h5
pnpm type-check
pnpm lint
pnpm test:run
```

页面采用 hash 路由。首次打开是空白游客手账；「看看示例手账」主动载入原型内容，所有示例都有标记。四个 Tab 为如期、纪念、手记、我的；中央「＋」提供写手记与添加纪念日入口。

手机模拟登录入口：我的 → 登录。使用符合大陆手机号格式的号码，验证码固定 **9999**；也可点击获取验证码，展示 60 秒重发倒计时。不发送短信、不验证号码归属、不创建服务端 token。游客与各手机号各自保存一份本地手账，登录不会自动搬运游客数据。退出不会删除手账。

## 已实现

- 首页将至、今天、记得；公历日期动态计算；首页情感条最多选择一个纪念日。
- 纪念日列表、分类和搜索、新建、编辑、详情、删除、年度/一次性重复、日历及快速选年。
- 手记列表、搜索、按月及照片筛选、新建、编辑、详情和删除。
- 手记发生日期与关联纪念日日期分开保存；每篇最多关联一个纪念日的一次日期，详情按关联年份整理。
- 最多六张照片，H5 压缩为 JPEG data URL，在本地持久化；支持预览与移除。照片总量受浏览器存储配额限制，写入失败保留输入并提示。
- 通过「稍后」选择保存草稿或放弃修改；草稿入口在我的，仅保留一篇，覆盖前确认。
- 默认提醒偏好、各纪念日规则、JSON 备份导出及校验后恢复；删除和覆盖有确认。
- 手记文字复制，可自行粘贴分享。

## 分层和 API 接入位置

| 层 | 位置 | 职责 |
|---|---|---|
| 页面与公共 UI | `src/pages/journal/`、`src/components/fg-journal-*` | 表单与展示，不直接操作浏览器存储 |
| 状态与用例 | `src/store/journal.ts` | 创建、编辑、删除、解除关联、账号数据载入；保存成功再更新页面状态 |
| 领域模型 | `src/domain/journal.ts` | 类型、日期规则与数据边界校验 |
| 数据仓储 | `src/repositories/journal.ts` | `JournalRepository.load/save` 异步契约；当前通过 Pinia 持久化适配器保存，写后读回确认并在失败时回滚 |
| 登录适配器 | `src/api/journal/auth.ts` | `PhoneAuthGateway.sendCode/login`，当前为固定验证码的本地实现 |
| 本地身份 | `src/store/local-session.ts` | 本地模拟身份持久化，与原有服务端 token store 分离 |
| H5 平台接缝 | `src/utils/journal-media.ts`、`journal-backup.ts` | 图片压缩、文件选择、备份下载；浏览器 API 由 H5 条件编译隔离 |
| 视觉令牌 | `src/style/journal-tokens.css` | 保留原型令牌名与色值，渐变占位画面单独保存在 `journal-photos.css` |

接入后端时，用走 `src/http` 的实现替换仓储和登录网关。将本地身份换成现有 token store 的服务端认证，并配合路由权限策略；不能将模拟账号当成已验证身份。照片上传、服务端分页与细粒度 CRUD 需随实际 API 契约扩展仓储。当前快照式 load/save 契约服务于单机版，未来可拆分查询及实体操作，页面组件和领域规则继续复用。

## 明确的首版边界

- 当前只验收 H5，尚未完成 App 真机适配。
- 提醒偏好能保存，但不发送系统通知；页面明确显示状态。
- 不接入真实短信、云同步、家庭协作、图片/链接分享、PDF 导出、农历和回收站。
- 日期仅公历；2 月 29 日在非闰年取 2 月 28 日，闰年恢复原始月日。
- 地点和天气手动填写，不申请位置权限，也不伪造自动获取的结果。
- 数据保存在当前浏览器中，清除站点数据会丢失；JSON 备份不含登录会话。
- 本地账号划分用于演示切换，不构成隐私安全隔离或真实认证。
- 字体使用原型 fallback 栈，不依赖外部字体请求；字体资源尚未本地化打包。

## 验证范围

领域测试覆盖跨年、闰日、当天与过去事件以及无效备份。登录测试覆盖号码校验和固定验证码。业务测试覆盖删除解除关联、失败重试和账号切换；仓储测试使用真实 Pinia 持久化插件验证恢复、配额失败回滚与损坏数据过滤。Chromium 浏览器已验证模拟登录、账号隔离、创建/编辑/返回/刷新、删除解除关联、草稿恢复、照片持久化、备份导入导出及 20 条到 26 条的滚动分页。390px 和 320px 手机宽度及桌面预览已检查。完整检查 `pnpm check` 通过（63 项测试），H5 生产构建通过。

## 更新：重要的人

入口为「我的 → 重要的人」。人物资料包含称呼、关系（可自定义）、可选生日、备注。人物是个人手账中的记录对象，不是应用成员；数据继续按游客和手机号隔离。

- 纪念日、手记编辑页使用「与谁有关」，支持多人选择和现场创建；详情使用「一起记得」，人物标签可进入人物回看页。
- 人物页展示有关的纪念日和手记；列表支持称呼/关系搜索及人物筛选。归档人物默认不出现在新选择中，已有选择和历史关联保留。
- 从纪念日创建手记会预填人物，之后两份记录的关联各自独立；写手记过程中关联纪念日时，由用户确认是否合并带入人物。
- 生日可不填写；可以填写完整出生日期，或只填月日。仅月日模式直接选择月、日，不显示年龄；非闰年 2 月 29 日按 2 月 28 日纪念。
- 设置生日会创建年度生日纪念日，也可以复用未被其他人物认领的生日纪念日，保留其提醒、标题和历史手记。
- 人物的 `birthdayEventId` 指向生日纪念日，日期只存在该纪念日上。`birthdayPersonId` 为反向关联；人物和纪念日入口始终编辑同一条事件。未知年份使用闰年基准配合 `yearUnknown` 存储，不将基准年份展示为出生年份。
- 生日主人始终保留在对应纪念日的人物关联里。修改生日或人物不会改写既有手记的发生日期、正文及人物选择。
- 清空生日可以保留原生日纪念日，也可以确认后同时删除。删除生日纪念日会同步清空人物生日；历史手记保留，解除该纪念日关联。
- 删除人物只解除人物关联，纪念日、生日纪念日、手记和草稿均保留。归档是保留人物资料及历史关系的可逆选择。
- 新增 `src/domain/people.ts` 处理人物与生日的原子变更；人物操作仍通过同一仓储保存，失败不会留下半个人物或半个生日。
- 旧本地数据在读取时补空人物列表，不根据旧正文或标签猜测人物。新备份格式为 v2，导入同时兼容 v1 与 v2，并校验人物与生日关系。
- 后续开发与提交直接在 `master`，检查通过后推送并沿用 Pages 自动发布。
